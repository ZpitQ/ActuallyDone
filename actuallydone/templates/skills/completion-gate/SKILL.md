# 完成门禁

**完成 = 存在一份回执，它的树哈希等于当前代码的树哈希，且每一步都通过。**

不是「我跑过测试了」，不是「日志贴在上面」，不是勾了清单。这些都由被检者自己撰写，
挡不住四种伪完成：贴过期日志、转述而不真跑、**跑完门禁再改代码**、编一个不存在的用例名。

## 怎么用

```bash
{{ADONE}} gate run     # 真跑门禁并写回执，交付前跑一次
{{ADONE}} gate check   # 校验回执是否新鲜且全绿，约 1 秒，随时可跑
```

宣称完成时，引用回执 ID（形如 `20260810-213012`）与树哈希前 12 位，不要复述测试日志。
一句就够：「门禁回执 20260810-213012（树 e3a91c…），全部用例通过{{COVERAGE_CLAIM}}。」

门禁只回答「这次改动是否全绿」。要看整个项目的健康度（技能沉淀、代码质量、需求台账、AI 物料），
跑 `{{ADONE}} health`——它默认读这份回执而不重跑测试，`--all` 才会重跑门禁。

## 回执里有什么

`{{RECEIPT_PATH}}`，由脚本写，不要手改：

- `tree.hash` / `tree.file_count`：受监视代码树（{{WATCH_DESC}}）的内容哈希。
  **改一个字符哈希就变**，这是「跑完再改」被抓住的原因。
- `tests.passed_names`：通过用例名全集。验收契约靠它证明「这条需求真有用例跑过」。
- `steps`：{{GATE_STEPS}}，每步的命令、退出码、输出尾巴。
- `coverage.percent`：{{COVERAGE_DESC}}

## check 说不通过时

按提示逐条处理，**不要绕过**。常见几种：

- **「回执已过期」**：你在跑完门禁之后改了代码。重跑 `{{ADONE}} gate run`。这是最常见的一种，
  也是最该老实重跑的一种——哪怕只改了一行注释，也没人能替你保证它无害。
- **「有用例被条件跳过」**：整批用例因为连不上依赖（数据库、外部服务）被跳过了，
  这种「绿」什么也不证明。把依赖起起来重跑。
- **「用例 X 没有出现在回执的通过名单里」**：契约绑的用例没跑过或没通过，见
  [acceptance-contract](../acceptance-contract/SKILL.md)。
- **「N 个用例消失了 / 跳过涨了」**：假绿检测报的，见
  [test-integrity](../test-integrity/SKILL.md)。
- **「判据被放松且没有记账」**：你改的不是代码，是尺子——缩了受监视范围、换了步骤命令、
  删了检查项或验收契约、把用例名加进了豁免名单。改判据本身不是错，不说一声才是。
  确属合理时 `{{ADONE}} policy --accept "为什么"` 记一笔再继续；不是有意为之就改回去。
- **「回执的自哈希对不上 / 与证据链头对不上」**：`{{RECEIPT_PATH}}` 被手改过，或者
  被换成了另一份旧回执。回执只能由 `{{ADONE}} gate run` 产出，重跑一次。

跑不了门禁时（本机缺依赖、装不上包），**直接说卡在哪一步、看到什么输出**，让人来判断。
谎报一句「已完成」的代价，比说一句「跑不了」大得多。

## 判据变更要记账

「让门禁变绿」有两条路：把代码改对，或者把尺子改短。后者包括缩小 `gate.watch_roots`、
把测试命令换成只跑一条、删掉一份验收契约、把用例名塞进 `tests.baseline_exempt`。
这些都会被判据锁比对出来：

```bash
{{ADONE}} policy                                   # 有没有人把门槛悄悄调低
{{ADONE}} policy --accept "为什么这次要放松，理由写清楚"
```

判据基线、假绿基线、证据链头三份都建议入库——它们是证据，不是缓存，入库之后
每一次放松都会出现在 diff 里。

## 交付时把结论交给别人验

你自己跑 `gate check` 证明的是「证据自洽」，而你正是被检者。真正的复核由一个**没参与实现**
的执行者做：开一个新会话（换个模型更好），让它按
[independent-check](../independent-check/SKILL.md) 跑 `{{ADONE}} audit`。

你这边要做的只有一件事：**把证据留全**（回执是 `gate run` 产的、判据放松已经 `policy --accept`
记过账、契约条目绑的是真用例名），然后交出回执 ID 与树哈希——**不要转述你的实现思路**，
复核者不该看你的推理过程。它跑出的结论落在 `{{STATE_DIR}}/audit.json`，不会覆盖你的回执。

## 诚实的边界

这套机制**提高伪造成本，不是密码学级不可伪造**。Agent 有写文件权限，理论上能重算整条回执链
并同步改掉基线。缓解是回执由脚本写、带自哈希与链、内容含树哈希与命令输出，
任何人可以用 `{{ADONE}} gate check --explain` 独立复核，交付前还可以
`{{ADONE}} gate check --spotcheck` 抽两条用例当场真跑、由第二个模型 `{{ADONE}} audit --rerun` 全量重跑。
要做到真正不可伪造，需要一个 Agent 无权写入的执行者（CI），路径写在
[verified-delivery/references/sandbox.md](../verified-delivery/references/sandbox.md)。
